# 部署指南

本文描述 **v0.1.0 当前代码**的真实部署方式。设计总纲 §10 里提到的「单 Jar 内置前端」「Tauri 套壳」「Quartz 持久化」属于规划，本文不做假设。

## 1. 环境要求

| 组件 | 版本 | 备注 |
| --- | --- | --- |
| JDK | 17+ | 运行 `minidesk.jar` |
| Maven | 3.9+ | 源码构建，运行 Jar 时不需要 |
| Node.js | 20.19+ / 22.12+ | 仅构建前端需要 |
| Nginx | 任意较新版本 | 生产推荐；托管静态资源 + 反代 `/api` |
| SQLite | 随 JDBC 驱动内置 | 无需单独安装数据库服务 |

## 2. 本地开发

```bash
# 终端 A：后端（必须在 backend/ 下运行，数据目录相对工作目录）
cd backend
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=18080"

# 终端 B：前端
cd frontend
npm ci
npm run dev
```

- 前端 `http://127.0.0.1:5180`，Vite 把 `/api` 代理到 `18080`（`vite.config.ts` 的 `server.proxy` 与 `preview.proxy` 都已配置）。
- 后端 `http://127.0.0.1:18080`，接口前缀 `/api`。
- 启动时执行 `classpath:db/schema-sqlite.sql` 建表，`SchemaUpgrade` 补增量列，`DataInitializer` 写入角色、权限与站点配置，全程幂等。
- **显式传 `--server.port`**：部分环境会注入 `PORT` 变量，可能覆盖 `server.port` 导致端口莫名被占用。

## 3. 首次初始化与安全

1. 访问登录页注册。**第一个注册的用户自动成为 ADMIN**，之后注册的都是 MEMBER。
2. 公网部署务必先设置 `MINIDESK_CLAIM_TOKEN`，注册时填写正确令牌才能领取管理员；否则任何先到访客都能拿到最高权限。
3. 用管理员进 `/console`：
   - 站点配置：站点名称、开放注册开关
   - 品牌设置：横版 Logo、方形 Logo
   - 邮件设置：SMTP 主机 / 端口 / 账号 / 密码 / 发件人、启用邮箱注册
   - 概览、用户管理、登录与操作日志
4. 用户端「设置 → 集成配置」填和风天气 API Host 与 Key。未配置、被禁用或请求失败时自动降级为模拟天气并显示「模拟」角标；Key 以 AES-GCM 加密存储，界面只回显掩码。
5. 邮箱验证码注册入口只在 SMTP 配置并启用后才出现。

> 仓库不含任何数据库文件或默认管理员密码。首次启动是空库。

## 4. 生产部署（前后端分离 + Nginx）

### 4.1 构建

```bash
cd frontend
npm ci
npm run typecheck
npm run build            # 产物 frontend/dist/

cd ../backend
mvn -DskipTests package  # 产物 backend/target/minidesk.jar
```

当前 `minidesk.jar` **不包含前端静态资源**，需要由 Nginx 单独托管 `dist/`。

### 4.2 目录建议

```
/srv/minidesk/
├── backend/
│   ├── minidesk.jar
│   └── data/            # SQLite 库、密钥、上传文件
└── frontend/
    └── dist/
```

### 4.3 后端服务（systemd 示例）

```ini
[Unit]
Description=MiniDesk
After=network.target

[Service]
Type=simple
User=minidesk
WorkingDirectory=/srv/minidesk/backend
Environment=SA_TOKEN_SECRET=换成32字节以上随机串
Environment=MINIDESK_CLAIM_TOKEN=换成自定义令牌
ExecStart=/usr/bin/java -jar /srv/minidesk/backend/minidesk.jar --server.port=18080
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

后端只监听 `127.0.0.1`，不要直接暴露到公网。若必须监听其他地址，用 `--server.address=127.0.0.1` 配合 Nginx。

### 4.4 Nginx（含 SPA fallback）

```nginx
server {
    listen 443 ssl http2;
    server_name desk.example.com;

    ssl_certificate     /etc/ssl/desk.example.com.crt;
    ssl_certificate_key /etc/ssl/desk.example.com.key;

    root /srv/minidesk/frontend/dist;
    index index.html;

    client_max_body_size 24m;   # 与后端 multipart 限制一致

    location /api/ {
        proxy_pass http://127.0.0.1:18080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }

    location / {
        try_files $uri $uri/ /index.html;   # 刷新子路由不 404
    }
}
```

附件读取接口 `/api/files/{id}/raw?token=...` 也在 `/api/` 下，无需额外 location。

### 4.5 上线检查

按 [SECURITY.md](../SECURITY.md) 的清单逐项核对：JWT 密钥、领取令牌、注册开关、HTTPS、数据目录权限、备份、日志脱敏。

## 5. 数据目录与备份

```
backend/data/
├── minidesk.db         SQLite 主库（WAL 模式，另有 -wal / -shm）
├── .secret             集成 Key 的加密密钥，丢失后已加密的 Key 无法解开
├── uploads/            用户上传的附件与头像
└── branding/           后台上传的站点 Logo
```

`data/` 是**唯一需要持久化**的目录，且已被 `.gitignore` 排除，绝不入库。

推荐停服备份（避免 WAL 未合并导致恢复不完整）：

```bash
systemctl stop minidesk
cd /srv/minidesk/backend

# 有 sqlite3 CLI 时用在线备份 API，最稳
sqlite3 data/minidesk.db ".backup '/srv/backup/minidesk-$(date +%F).db'"

# 没有 CLI 时，停服后连同 -wal / -shm 一起复制
tar czf /srv/backup/minidesk-data-$(date +%F).tar.gz data/

systemctl start minidesk
```

备份包包含用户数据，**设置最小权限并加密存放**，不要放到 Web 可访问目录。恢复时用备份覆盖 `data/` 后重启服务，版本不一致时先确认 `SchemaUpgrade` 的补列是否兼容。

## 6. 数据库切换现状

`backend/src/main/resources/db/` 已提供三套完整 DDL：

| 脚本 | 初始化方式 |
| --- | --- |
| `schema-sqlite.sql` | 应用启动自动执行（默认） |
| `schema-mysql.sql` | `mysql -u root -p minidesk < schema-mysql.sql`（需先建 utf8mb4 数据库） |
| `schema-postgresql.sql` | `psql -d minidesk -f schema-postgresql.sql` |

**当前版本运行时只支持 SQLite。** MySQL / PostgreSQL 脚本用于建空库与二次开发参考，直接把 `SPRING_DATASOURCE_URL` 改成 MySQL / PG **不能启动**，还需完成：

1. `pom.xml` 增加对应 JDBC 驱动；
2. 增加 `application-mysql.yml` / `application-pg.yml`，切换 `schema-locations` 与 `spring.sql.init` 行为；
3. `SchemaUpgrade` 的 `pragma table_info` 改为对应方言的元数据查询；
4. `DataInitializer` 的 `insert or ignore` 改为 `ON DUPLICATE KEY UPDATE` / `ON CONFLICT DO NOTHING`；
5. 复核自定义 TypeHandler 与所有手写 SQL 的方言差异。

这些属于 v0.3 计划，请勿在生产环境直接切库。

## 7. 升级

1. 先按第 5 节备份 `data/`。
2. 替换 `minidesk.jar` 与前端 `dist/`。
3. 重启后端：`SchemaUpgrade` 会自动补新增列，不需手工执行 ALTER。
4. 清一下浏览器缓存（前端资源带 hash，主题变量变化时可强刷）。
5. 看启动日志有无 `schema upgrade` 相关告警，再走一遍登录、待办、笔记、附件上传。

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 后端启动报端口被占用 | 环境注入了 `PORT`，显式加 `--server.port=18080`；或先用 `netstat` / `lsof` 查占用进程 |
| 前端 5180 起不来 | Vite 开了 `strictPort`；关掉占用 5180 的进程，或改 `vite.config.ts` 端口 |
| 首页天气一直显示「模拟」 | 没配 Key、集成被禁用、Host 不对或网络超时（后端 3 秒超时后降级）；到「设置 → 集成配置」测试连接，看后端日志 |
| 注册页没有「邮箱注册」 | SMTP 未配置或未启用，到 `/console` 邮件设置里完成并启用 |
| 上传大文件失败 | 后端限制单文件 20MB / 请求 24MB，Nginx 也要设 `client_max_body_size 24m` |
| 刷新 `/todo`、`/console` 报 404 | Nginx 缺 `try_files ... /index.html` 的 SPA fallback |
| 图标偶发不显示 | `@iconify/vue` 默认走在线图标 API；离线环境需自建图标集或改用本地 SVG |
| `database is locked` | 已开启 WAL；不要多个进程同时写同一个 db 文件，桌面端与服务端共库时尤其注意 |
| 忘记管理员密码 | 当前没有 CLI 兜底。先备份，再在空库重新注册，或在数据库内重置密码哈希（BCrypt） |
| 后台 `/console` 进不去 | 该路由要求 ADMIN 角色；确认账号角色，且不要删除 / 禁用唯一的 ADMIN |

更多设计层面的取舍（多端、单 Jar、Quartz、备份策略）见 [MiniDesk开发文档.md](./MiniDesk开发文档.md)，其中标注为「规划」的章节尚未实现。
