# 部署指南

本文描述 **v0.1.0 当前代码**的真实部署方式。设计总纲 §10 里提到的「单 Jar 内置前端」「Tauri 套壳」「Quartz 持久化」属于规划，本文不做假设。

## 1. 环境要求

| 组件 | 版本 | 备注 |
| --- | --- | --- |
| JDK | 17+ | 运行 `minidesk.jar` |
| Maven | 3.9+ | 源码构建，运行 Jar 时不需要 |
| Node.js | 20.19+ / 22.12+ | 仅构建前端需要 |
| Nginx | 任意较新版本 | 生产推荐；托管静态资源 + 反代 `/api` |
| SQLite | 随 JDBC 驱动内置 | 无需单独安装数据库服务 |

## 2. 本地开发

```bash
# 终端 A：后端（数据目录默认 ./data，可用 MINIDESK_DATA_DIR 改成绝对路径）
cd backend
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=18080"

# 终端 B：前端
cd frontend
npm ci
npm run dev
```

- 前端 `http://127.0.0.1:5180`，Vite 把 `/api` 代理到 `18080`（`vite.config.ts` 的 `server.proxy` 与 `preview.proxy` 都已配置）。
- 后端 `http://127.0.0.1:18080`，接口前缀 `/api`。
- 启动时执行 `classpath:db/schema-sqlite.sql` 建表，`SchemaUpgrade` 补增量列，`DataInitializer` 写入角色、权限与站点配置，全程幂等。
- **显式传 `--server.port`**：部分环境会注入 `PORT` 变量，可能覆盖 `server.port` 导致端口莫名被占用。

## 3. 首次初始化与安全

1. 访问登录页注册。**第一个注册的用户自动成为 ADMIN**，之后注册的都是 MEMBER。
2. 公网部署务必先设置 `MINIDESK_CLAIM_TOKEN`，注册时填写正确令牌才能领取管理员；否则任何先到访客都能拿到最高权限。
3. 用管理员进 `/console`：
   - 站点配置：站点名称、开放注册开关
   - 品牌设置：横版 Logo、方形 Logo
   - 邮件设置：SMTP 主机 / 端口 / 账号 / 密码 / 发件人、启用邮箱注册
   - 概览、用户管理、登录与操作日志
4. 用户端「设置 → 集成配置」填和风天气 API Host 与 Key。未配置、被禁用或请求失败时自动降级为模拟天气并显示「模拟」角标；Key 以 AES-GCM 加密存储，界面只回显掩码。
5. 邮箱验证码注册入口只在 SMTP 配置并启用后才出现。

> 仓库不含任何数据库文件或默认管理员密码。首次启动是空库。

## 4. 生产部署（前后端分离 + Nginx）

> 也可以打成单 Jar：`python scripts/build_single_jar.py` 会构建前端、执行
> `mvn -Psingle-jar package`，产物 `backend/target/minidesk.jar` 内含 `static/`。
> 直接 `java -jar minidesk.jar --server.port=18080` 即可访问页面与接口，
> 无需 Nginx 的 SPA fallback（`SpaFallbackConfig` 只在检测到 `static/index.html` 时生效）。
> 下面的分离部署方式适合前端独立托管或需要 CDN 的场景。

### 4.1 构建

```bash
cd frontend
npm ci
npm run typecheck
npm run build            # 产物 frontend/dist/

cd ../backend
mvn -DskipTests package  # 产物 backend/target/minidesk.jar
```

当前 `minidesk.jar` **不包含前端静态资源**，需要由 Nginx 单独托管 `dist/`。

### 4.2 目录建议

```
/srv/minidesk/
├── backend/
│   ├── minidesk.jar
│   └── data/            # SQLite 库、密钥、上传文件
└── frontend/
    └── dist/
```

### 4.3 后端服务（systemd 示例）

```ini
[Unit]
Description=MiniDesk
After=network.target

[Service]
Type=simple
User=minidesk
WorkingDirectory=/srv/minidesk/backend
Environment=SA_TOKEN_SECRET=换成32字节以上随机串
Environment=MINIDESK_CLAIM_TOKEN=换成自定义令牌
ExecStart=/usr/bin/java -jar /srv/minidesk/backend/minidesk.jar --server.port=18080
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

后端只监听 `127.0.0.1`，不要直接暴露到公网。若必须监听其他地址，用 `--server.address=127.0.0.1` 配合 Nginx。

### 4.4 Nginx（含 SPA fallback）

```nginx
server {
    listen 443 ssl http2;
    server_name desk.example.com;

    ssl_certificate     /etc/ssl/desk.example.com.crt;
    ssl_certificate_key /etc/ssl/desk.example.com.key;

    root /srv/minidesk/frontend/dist;
    index index.html;

    client_max_body_size 520m;  # 与后端 multipart 上限一致（恢复包可含附件）

    location /api/ {
        proxy_pass http://127.0.0.1:18080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For  $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }

    location / {
        try_files $uri $uri/ /index.html;   # 刷新子路由不 404
    }
}
```

附件读取接口 `/api/files/{id}/raw?token=...` 也在 `/api/` 下，无需额外 location。

### 4.5 上线检查

按 [SECURITY.md](../SECURITY.md) 的清单逐项核对：JWT 密钥、领取令牌、注册开关、HTTPS、数据目录权限、备份、日志脱敏。

### 4.6 部署后冒烟验证

```bash
MINIDESK_BASE_URL=https://desk.example.com MINIDESK_ADMIN_PASSWORD='...' \
  python scripts/smoke_test.py
```

脚本只依赖 Python 标准库，会验证静态资源与 SPA 路由、登录、定时任务手动触发与 Cron
真实触发、备份下载与快照记录一致性、审计参数脱敏。默认**不会**上传恢复包
（`--queue-restore` 才会，且只在重启时生效）；后端未内置前端时静态检查自动跳过。
脚本会创建一份备份、触发几个任务并短暂改一次 Cron 后改回，属于可控写入。

### 4.7 Docker 单镜像部署（推荐）

官方镜像把 Vue 3 前端打进 Spring Boot 单 Jar，容器里只有一个 Java 进程：页面在 `/`、
接口在 `/api/**`，SQLite 默认落在数据卷 `/data`。不需要 Nginx 做 SPA fallback。

```bash
export SA_TOKEN_SECRET="$(openssl rand -hex 32)"
export MINIDESK_CLAIM_TOKEN='换成自定义令牌'   # 公网部署必填，防止抢注管理员
docker compose -f deploy/docker-compose.yml up -d
```

打开 `http://服务器IP:18080` 注册；**第一个注册者成为管理员**（设置了领取令牌则需填写）。
`MINIDESK_PORT` 只改宿主映射端口，容器内固定 18080（`HEALTHCHECK` 依赖该端口）。
反向代理放在容器外，把域名流量转到 18080 即可。

镜像里的约定：

| 项 | 值 |
| --- | --- |
| 数据卷 | `/data` = `minidesk.db`、`.secret`、`uploads/`、`branding/`、`backups/`、恢复包 |
| 运行用户 | 非 root，`minidesk` (uid 10001) |
| 探活 | `/api/auth/register-config`（鉴权白名单，不返回用户数据） |
| 时区 | `Asia/Shanghai` |
| 端口 | 容器内 18080 |

**不要设置 `SPRING_DATASOURCE_URL`**：主库 URL 已跟随 `MINIDESK_DATA_DIR`，
单独覆盖会让「数据目录」与「数据库文件」两处配置分叉。备份与恢复照常用
`/console/backups`；上传恢复包后需要 `docker restart minidesk` 才生效。

本地构建镜像（仓库根执行，多阶段：Node 22 → Maven 3.9/JDK17 → JRE17）：

```bash
docker build --build-arg NPM_REGISTRY=https://registry.npmjs.org \
  -t minimscn/minidesk:0.1.0 .
```

打包后会校验 jar 内确实含 `BOOT-INF/classes/static/index.html`，避免发出页面全 404 的空壳。

#### 自动发布

`.github/workflows/docker-publish.yml` 用 GitHub Actions 发布到 Docker Hub
`<DOCKERHUB_USERNAME>/minidesk`：

1. 仓库 `Settings → Secrets and variables → Actions` 添加 `DOCKERHUB_USERNAME` 与
   `DOCKERHUB_TOKEN`（Access Token，需 Read & Write，不是登录密码）。
2. 发布：`git tag v0.1.0 && git push origin v0.1.0` → 推送 `0.1.0` / `0.1` / `latest`。
3. 推到 `main`（改源码、Dockerfile、deploy 或工作流）→ **只验证构建，不推送**。
4. Actions 页面手动 Run workflow：可关闭 `push` 只验证，或填 `version` 额外推送版本标签。

构建机在海外，工作流把 lockfile 里的 npmmirror 换回官方 npm 源，Maven 直连 Central；
只发 `linux/amd64`，需要 ARM 服务器时改 `platforms`。缺 Secrets 时会在「检查凭据」
一步给出明确提示，不会卡在登录。

### 4.8 知识库（MiniDocs）对接

知识库是**外部服务**，MiniDesk 只做代理，不托管文档。配置前先在 MiniDocs
（默认 `https://docs.minims.cn`）的「账号 → 第三方应用授权」签发一枚 `mdt_` 开头的
访问令牌；令牌只显示一次，服务端只存 SHA-256 摘要，丢了只能吊销重发。

- **推荐**：登录 MiniDesk →「设置 → 集成配置 → 知识库」，填站点地址与令牌、打开开关、保存，再点「测试连接」。
  站点地址填根地址即可（`https://docs.minims.cn`），后端自动补 `/api`；双镜像部署可填
  `https://host/minidocs` 或直接填接口基址。令牌 AES-GCM 加密存 `integration_config`，前端只回显掩码。
- **无人值守 / 容器部署**：设置环境变量 `MINIDESK_MINIDOCS_TOKEN`，首次启动会加密写入配置。
  只在「尚无任何用户配置过令牌」时导入，重启不会覆盖设置页里后来改过的值。注意导入给的是
  **最早注册的那个账号**（首个注册者即管理员），其他账号仍需各自在设置页配置。
- **权限**：只读令牌只能浏览；要把笔记沉淀成文档或新建知识库，签发时须选「读写」。
  令牌不能用于签发新令牌、改密码、登出——这些只能在知识库网页端做。
- **可见范围**：令牌代表其所有者本人，「我的知识库」可看到私有库（含所属组织内的库）；
  「站点公开库」走匿名门户，无需令牌也能看已发布内容。上游 `/api/search` 与 `/api/portal/**`
  是匿名白名单，带令牌也不会扩大可见范围，因此文档搜索基于目录树本地匹配。
- **不配置也能用**：知识库页会自动展示站点公开库；「我的知识库」则提示去设置页。
  正文实时读取不落库，目录树缓存 5 分钟，不会在 MiniDesk 里形成第二份内容。

> 生产环境请勿把令牌写进 compose 文件的字面量、镜像或日志；用环境变量或密钥管理注入。
> 全局搜索（`Ctrl+K`）暂不聚合知识库文档，避免高频交互被外部接口拖慢。

## 5. 数据目录与备份

```
backend/data/
├── minidesk.db         SQLite 主库（WAL 模式，另有 -wal / -shm）
├── .secret             集成 Key 的加密密钥，丢失后已加密的 Key 无法解开
├── uploads/            用户上传的附件与头像
├── branding/           后台上传的站点 Logo
├── backups/            后台生成的 ZIP 备份
├── restore-pending.zip 待生效的恢复包（存在时下次启动应用）
└── restore-last.json   上次恢复结果
```

`data/` 是**唯一需要持久化**的目录，且已被 `.gitignore` 排除，绝不入库。

改位置用 `MINIDESK_DATA_DIR`（建议绝对路径，例如 `MINIDESK_DATA_DIR=/srv/minidesk/data`）：
主库、`.secret`、附件、品牌资源、备份与恢复包**全部一起迁移**，不需要分别配置。
启动类会在连接池建立前自动创建该目录，因此单 Jar 放到一个空目录里直接
`java -jar minidesk.jar` 也能起来；也支持 `--minidesk.data-dir=` 命令行参数。

### 5.1 在线备份（推荐）

进入 `/console/backups`，点「立即备份」即可，运行中也能安全导出：后端用
`VACUUM INTO` 生成事务一致、不含 WAL 的快照，再把数据库、附件、品牌资源、
集成密钥与 `manifest.json` 一起打包成 ZIP。可以下载留档或删除旧备份。

自动备份由 `autoBackup` 定时任务每天 03:00 触发，按站点配置 `backup_keep`（默认 7）
保留最近几份，多余的文件与记录一起清理。

### 5.2 恢复

1. 在「备份与恢复」点「选择恢复包」，上传一份本系统生成的 ZIP；
2. 后端只做格式校验并落成 `data/restore-pending.zip`，**不会立即覆盖数据**；
3. 重启应用。`DeskApplication.main()` 会在 Spring 启动前校验 ZIP 路径、解压体积、
   SQLite 文件头与 `sys_user` 表，把当前库另存为 `minidesk.pre-restore-<时间戳>.db`，
   再替换数据库并覆盖附件、品牌资源和密钥；任何一步失败都自动回滚到原库；
4. 结果写入 `data/restore-last.json`，后台「恢复状态」可以看到。

备份 ZIP **不包含** `backups/` 目录（避免自我嵌套），所以已有的备份文件仍留在磁盘上。
恢复包包含用户数据，设置最小权限并加密存放，不要放到 Web 可访问目录。

### 5.3 手工兜底

没有后台可用时，停服后整目录打包仍然有效（务必包含 `-wal` / `-shm`）：

```bash
systemctl stop minidesk
cd /srv/minidesk/backend
sqlite3 data/minidesk.db ".backup '/srv/backup/minidesk-$(date +%F).db'"
tar czf /srv/backup/minidesk-data-$(date +%F).tar.gz data/
systemctl start minidesk
```

### 5.4 定时任务运维

`/console/jobs` 可以改 Cron、启停、立即执行并查看执行历史。改 Cron 会立刻重建触发器；
手动触发是同步执行，结果直接显示。所有执行都写 `job_exec_log`，成功摘要与失败原因都可见。

`logCleanup` 按 `audit_keep_days`（默认 180 天）清理登录、操作、任务日志与已读通知。
Quartz 用内存 job store，重启后按库里的定义重建；因此不支持 misfire 补跑与多实例集群。

## 6. 数据库切换现状

`backend/src/main/resources/db/` 已提供三套完整 DDL：

| 脚本 | 初始化方式 |
| --- | --- |
| `schema-sqlite.sql` | 应用启动自动执行（默认） |
| `schema-mysql.sql` | `mysql -u root -p minidesk < schema-mysql.sql`（需先建 utf8mb4 数据库） |
| `schema-postgresql.sql` | `psql -d minidesk -f schema-postgresql.sql` |

**当前版本运行时只支持 SQLite。** MySQL / PostgreSQL 脚本用于建空库与二次开发参考，直接把 `SPRING_DATASOURCE_URL` 改成 MySQL / PG **不能启动**，还需完成：

1. `pom.xml` 增加对应 JDBC 驱动；
2. 增加 `application-mysql.yml` / `application-pg.yml`，切换 `schema-locations` 与 `spring.sql.init` 行为；
3. `SchemaUpgrade` 的 `pragma table_info` 改为对应方言的元数据查询；
4. `DataInitializer` 的 `insert or ignore` 改为 `ON DUPLICATE KEY UPDATE` / `ON CONFLICT DO NOTHING`；
5. 复核自定义 TypeHandler 与所有手写 SQL 的方言差异。

这些属于 v0.3 计划，请勿在生产环境直接切库。

## 7. 升级

1. 先按第 5 节备份 `data/`。
2. 替换 `minidesk.jar` 与前端 `dist/`（单 Jar 模式只需替换 jar）。若之前上传过恢复包，
   本次重启会先执行恢复再启动服务，请确认这是预期行为。
3. 重启后端：`SchemaUpgrade` 会自动补新增列，不需手工执行 ALTER。
4. 清一下浏览器缓存（前端资源带 hash，主题变量变化时可强刷）。
5. 看启动日志有无 `schema upgrade` 相关告警，再走一遍登录、待办、笔记、附件上传。

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 后端启动报端口被占用 | 环境注入了 `PORT`，显式加 `--server.port=18080`；或先用 `netstat` / `lsof` 查占用进程 |
| 前端 5180 起不来 | Vite 开了 `strictPort`；关掉占用 5180 的进程，或改 `vite.config.ts` 端口 |
| 首页天气一直显示「模拟」 | 没配 Key、集成被禁用、Host 不对或网络超时（后端 3 秒超时后降级）；到「设置 → 集成配置」测试连接，看后端日志 |
| 注册页没有「邮箱注册」 | SMTP 未配置或未启用，到 `/console` 邮件设置里完成并启用 |
| 上传大文件失败 | 后端限制单文件 512MB / 请求 520MB，Nginx 也要设 `client_max_body_size 520m` |
| 上传恢复包后数据没变化 | 设计如此：恢复包排队等重启生效，到「备份与恢复」看恢复状态并重启应用 |
| 定时任务改了 Cron 没生效 | 检查任务开关是否开启；非法 Cron 会被拒绝（错误码 60052），原配置保留 |
| 单 Jar 启动后刷新子路由 404 | 确认用了 `-Psingle-jar` 构建且 jar 内含 `static/index.html`；`SpaFallbackConfig` 依赖它 |
| 刷新 `/todo`、`/console` 报 404 | Nginx 缺 `try_files ... /index.html` 的 SPA fallback |
| 图标偶发不显示 | `@iconify/vue` 默认走在线图标 API；离线环境需自建图标集或改用本地 SVG |
| `database is locked` | 已开启 WAL；不要多个进程同时写同一个 db 文件，桌面端与服务端共库时尤其注意 |
| 忘记管理员密码 | 当前没有 CLI 兜底。先备份，再在空库重新注册，或在数据库内重置密码哈希（BCrypt） |
| 后台 `/console` 进不去 | 该路由要求 ADMIN 角色；确认账号角色，且不要删除 / 禁用唯一的 ADMIN |

单 Jar、Quartz 调度、备份恢复与移动端导航已按上面各节实现；Tauri 与三库运行时适配仍未实现。
更多设计层面的取舍见 [MiniDesk开发文档.md](./MiniDesk开发文档.md)，其中标注为「规划」的章节不代表现状。
